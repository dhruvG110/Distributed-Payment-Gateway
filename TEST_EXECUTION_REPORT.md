## Bugs discovered and fixes applied

- **Auth `/me` absent (confirmed by source and HTTP):** `GET /api/auth/me` returns 404 (`Cannot GET /api/auth/me`). This does not satisfy the requested `/me` workflow. Proposed fix: add a JWT-protected route returning safe user fields, if desired; no change made.
- **Credential disclosure risk (confirmed by source inspection and resolved for test execution):** Wallet and Payment JWT middleware logged the incoming `access_token` cookie; Payment internal authentication logged the supplied `x-internal-secret`. Removed only those three logging calls, syntax-checked, and confirmed the service listeners restarted.
- **Correction to an earlier report entry:** The earlier claim that Wallet's adapter reads `DB_URL` was incorrect. Direct source reinspection of `wallet-service/db.js` shows it reads `DATABASE_URL`, and a scoped query using that Wallet Prisma client matched the exact QA wallets returned by the live API. The earlier mismatch finding is withdrawn.
- **Insufficient-balance payment remains nonterminal (confirmed by live HTTP and internal lookups):** Payment creation returned HTTP 202 with `reconciliationRequired: true`; Payment stayed `processing` with `next_retry_at: null`, Wallet operations were empty, and Ledger returned 404. Recommended fix: use the existing read-only Wallet/Ledger lookups to verify no movement, then safely transition this definitively rejected payment to `failed` and clear retry state. No production-code change made, consistent with the instruction to report bugs before fixing them.
- **Notification JWT runtime configuration mismatch (confirmed and corrected for the retest process):** Auth and Notification `.env` JWT values match, but the original Nodemon listener rejected the Auth cookie and a token signed with the local configured key. With user approval, that specific listener was stopped and Notification restarted with `JWT_SECRET` explicitly supplied from its `.env`; a token signed with that value then received HTTP 200. Auth-issued cookies then passed the full Notification history/read/ownership/cursor/delete retest. No source code or `.env` value was changed.
- **Reconciliation internal-secret configuration drift (confirmed live):** The value in Reconciliation's local `.env` received 401, while the value from Payment's local `.env` was accepted by the running Reconciliation API for the successful-payment run and run lookup. Values were not displayed. Recommended fix: align the Reconciliation runtime `INTERNAL_API_SECRET` with the internal caller configuration; no change made.
- **Payment test harness defect (confirmed):** The first PowerShell script assigned the reserved `$PID` variable and lost captured response output; a later script derived the payment ID only from the replay response, so its first detail/cancel URLs were malformed. Corrected authenticated requests were subsequently executed successfully for details and cancellation. These malformed requests are not counted as passing API tests.
- **Cancellation fixture harness failure (confirmed):** An earlier PowerShell harness attempted to parse mixed Prisma connection output as JSON and failed before a cancellation response could be recorded. Its pending Payment DB fixture was then processed by the running retry worker. A later live retest with fresh isolated fixtures successfully covered cancellation before reservation, repeated cancellation, and refusal after reserve; see PAY-17–PAY-19.

## Final readiness assessment

Not ready for a complete end-to-end conclusion. Two successful payments, their Wallet balance movements, committed reserve/credit operations, and balanced Ledger transactions were observed live. Retry scheduling, exhaustion safety, competing claims, expired-lease recovery, and lock ownership/renewal passed with isolated QA fixtures; this did not simulate a real worker process crash during an external operation. Wallet reserve/release and reserve/credit idempotency passed. A separate insufficient-balance payment remains stuck in `processing`, and Auth `/me` is missing. Payment’s Ledger-failure and Wallet-credit-timeout handling, actual mid-operation process-crash recovery, and QA data cleanup remain incomplete. The Notification user/internal workflows passed after correcting the process environment.
